# ADR-003 — Fecho comum por script e trilha fora do ciclo como add-on

- **Status:** accepted
- **Data:** 2026-11-15
- **Fase:** F-metodo-v8 (emenda ADR-001 e ADR-002)

## Contexto

Na F-metodo-v6 o `scripts/integrar-fase.sh` fazia o próprio `gh pr merge`. No projeto de onde este porte vem (Amplug, F-091 e F-098), isso mostrou três problemas: o merge recusava quando um check obrigatório ainda não tinha nascido ou o `main` andava no meio; o `gh pr merge --delete-branch` tira o worktree da branch, e o script caía com a pasta apagada antes de soltar a trava; e ninguém conferia, depois, se o PR entrou de fato, se sobrou branch e se o `main` local acompanhou. O mesmo projeto tinha um segundo tipo de trabalho, repetitivo e de conteúdo (um vídeo por vez, mesmo pipeline), que não cabia no ciclo plan → spec → code: o plan mode de cada item custava mais que o item, e a fase de conteúdo travava a fila das fases de produto. Esse trabalho precisava do mesmo encerramento seguro, sem o resto do ciclo.

## Decisão

1. **Uma rota de merge.** `scripts/fechar-pr.sh <pr> [--issue N]` é o único lugar que integra um PR: espera os checks, põe o PR em dia com `gh pr update-branch --rebase`, integra por `gh pr merge --rebase --delete-branch` sem `--admin`, fecha a issue e avança o `main` local só por fast-forward. `scripts/conferir-fecho.sh` cobra o resultado (`MERGED`, branches limpas, `main` igual ao `origin/main`, issue fechada) e responde `ok` ou `pendente: …`; pendência é falha. O `integrar-fase.sh` deixa de fazer merge: chama o `fechar-pr.sh` do checkout principal, segue de lá, solta a trava e roda o `conferir-fecho.sh`.
2. **Trilha fora do ciclo, opcional.** O projeto pode declarar uma trilha para conteúdo repetitivo: uma skill que roda o item num disparo, sem plan mode nem `SETUP.md`, a partir de uma issue com a label da trilha, tocando só uma lista fechada de caminhos de conteúdo. Ela fecha pelo mesmo fecho comum. Mudança no pipeline compartilhado é fase. O template traz o padrão (`AGENTS.md` §Trilha fora do ciclo), não uma trilha pronta.
3. **Canal em script.** `scripts/canal-avisar.sh` cumpre o aviso do contrato v1 (ADR-001), com os dois avisos sem pedido que só a trilha usa, `falha` e `fim`.

## Alternativas consideradas

- **Manter o merge dentro do `integrar-fase.sh`** — seriam duas rotas de merge assim que existisse uma trilha, e a correção de uma não chegaria à outra.
- **Trilha como fase enxuta** (spec mínima no `SETUP.md`) — ainda ocuparia o checkout como solitária e pediria plan mode por item; o custo que a trilha existe pra tirar.
- **Trilha pronta no template** — o conteúdo e o pipeline são do projeto; uma skill genérica de trilha seria código sem onde rodar.

## Consequências

O fecho ficou igual para fase e trilha, e testável com um `gh` falso (`scripts/fecho-gh-falso.sh`). Custa mais scripts no template (fecho, conferência e os testes), e o `integrar-fase.sh` passa a depender do `fechar-pr.sh`: projeto que copiar um sem o outro não integra. A trilha abre uma porta fora do ciclo; o que a mantém estreita é a lista fechada de caminhos no `AGENTS.md` do projeto, que é texto, não hook — se a trilha vazar para o pipeline duas vezes, vira candidata a hook (`AGENTS.md` §Observador de atrito).
